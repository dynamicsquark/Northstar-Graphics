Engine & GPU Pipeline Architecture

Strict separation between high-level scene/resource orchestration (NorthstarCore) and low-level Direct3D 12 command execution (NorthstarD3D12).

1. Modular Runtime Boundary

Northstar Graphics splits execution across two dynamically loaded shared libraries verified at startup via NORTHSTAR_ENGINE_API_VERSION:

  • NorthstarCore.dll: Owns scene graphs, O(1) incremental GPU Scene dirty tracking, reflection-driven constant/structured buffer materialization, NVG cluster hierarchy building and page residency, and NVS virtual shadow orchestration.
  • NorthstarD3D12.dll: Implements NorthstarBackend over Direct3D 12, managing descriptor heaps, resource state tracking and barrier batching, pipeline state caching, upload rings, and ExecuteIndirect command submission.

2. Persistent GPU Scene

Every RenderObject attached to a Scene maintains an inline O(1) dirty link. During RenderFrame(), CoreGPUSceneManager coalesces contiguous dirty object slots and uploads 160-byte GPUSceneObjectData records and skinning bone palettes to persistent GPU buffers, avoiding redundant CPU-to-GPU traffic for static or unmutated objects.

3. Northstar Virtual Geometry (NVG)

When a mesh is created with GeometryMode::Virtualized:

  1. Cluster DAG Construction: NVGBuilder partitions input triangles into clusters of up to 128 vertices/triangles, builds boundary-locked simplification groups across LOD levels, and packs quantized vertex attributes into 32 KiB virtual pages.
  2. Elastic Streaming Pool: Root LOD pages remain pinned in VRAM so coarse fallback geometry is always resident, while finer streaming pages are uploaded on demand within the configured NVGMemoryBudget.
  3. Two-Phase GPU Culling: Compute passes perform instance frustum/HZB culling and persistent BVH hierarchy traversal against the previous frame's HZB, rasterize visible clusters, rebuild the current HZB, and re-test newly disoccluded clusters in Phase 2 to prevent popping.

4. Northstar Virtual Shadows (NVS)

NVS replaces fixed cascade shadow maps with a unified GPU-driven virtual shadow page pool:

  • 2-Level Sparse Page Hierarchy: Maps directional toroidal clipmaps, spot perspective mip pyramids, and 6-face point light cubemaps onto physical 128×128 depth tiles.
  • Screen-Space Depth Feedback: Analyzes camera scene depth each frame to request only the virtual shadow pages actually visible on screen.
  • Indirect Caster Culling & Commit: Culls both standard and NVG virtualized shadow casters on the GPU, selectively clears dirty physical array slices, executes multi-bucket indirect draws, and promotes pages to VALID_SHADOW_DATA only after verified completion.
